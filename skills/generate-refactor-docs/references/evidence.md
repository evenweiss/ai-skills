# 页面与接口取证

生成初稿时读取关键取证；梳理现状、制定方案或审查时，仅按本次涉及的展示、输入、契约、权限及交接问题读取对应小节。取证不扩大改造或验收范围。

## 初稿前关键取证

生成迁移文档前，复用已有规则表或证据记录核对以下内容；其他模式由主技能链接本节时，仅需读取本节。

- **项目归属**：按[迁移范围](../SKILL.md#选择迁移范围)先区分修改与依赖；仅后端不要求目标前端项目，仅前端不要求新增目标后端项目。按实际涉及的页面与端确认旧、目标前端项目，按直接接口确认旧、目标后端与必要提供方；在现有范围表记录页面、接口、项目对应，区分实际修改与仅依赖。多个提供项目分别核对鉴权、信封、错误码、定义及序列化证据，不以同一页面或项目名相似推定规范一致；公共头部或共享接口的所属项目不能证明目标后端归属。目标未明确且影响方案时集中询问，不按依赖关系猜测。
- **操作与结果**：按实际操作核对输入处理、校验顺序、保存、展示、回填及失败结果，特别检查创建与编辑等入口的差异；不能只靠文档彼此一致证明覆盖完整。
- **必要契约**：先查可访问的提供方源码或可靠响应，核实直接影响本页结果的类型、筛选和转换；缺证时指出受影响结果，不把可查明事实笼统留到联调，也不扩大为全仓调查。
- **资源**：核对有业务意义的说明图、字典或规则文件的来源、可用性及必要版本依据。资源取得与消费语义确定分别检查，不默认需要冻结或上传副本。产品写可见内容和准确结果；消费算法及技术映射归方案，见[输入处理取证](evidence.md#输入处理与校验兼容取证)。

只汇总仍影响本次交付的缺口，按[文档设计验收边界](document-review.md#文档设计验收与实施验证)区分待决策与待验证，再按[集中确认规则](business-requirements.md#生成审查与交付)提问；已有答复不重复问。

## 取证范围与兼容基线

**结果终点与版本适用性**：按本页实际相关的输入与分支，核对提供方转换、序列化及最终模板/组件消费；这些环节已足以确定筛选、计算或呈现时，不再为同一结论追查整条发布链。源码声明或本地依赖只能证明对应代码的运行要求，不能直接证明旧实例版本；已确认兼容版本且无相关反证时，不另设实例绑定门槛。只有实际相关分支随运行版本或配置改变结果，才补能区分该分支的版本确认、具体配置项或样本，不默认索取镜像。区分源码已证结果与迁移后尚待运行验证的结果；关键字段类型、金额精度、错误或权限语义未知，仍按其实际影响补证，不能以缩减查询为由认定等价。

**取证范围与跨页交接**：从本次指定的页面、接口或项目入口取证；页面相关的仅后端先定位实际消费页面及其字段、错误动作和可见结果，仅前端先定位实际请求及必要提供方契约，再按解释本次结果所需追踪控制器、服务、权限与转换。未修改端不要求全仓取证，充分且可靠的契约与消费证据可复用；只在解释业务结果或迁移风险所需时继续追踪下游及其他调用方。跨页时先区分目标是发出的跳转还是接收后的行为，再按[方案中的范围与验证停止点](migration-plan.md#制定与开发者审查)取证；跳转地址不能证明接收结果，读取接收代码也不自动扩大改造和验收范围。

**跨项目链路**：沿本次业务场景记录各项目的调用顺序、交接字段来源与转换、失败传播及副作用，标明证据版本和未知阶段。共享逻辑集中取证、说明适用消费者；只追到能解释目标结果和兼容影响的位置，不扩大为全域或全仓调查。页面到接口、项目的定位可复用总览或现有表，不能只列项目清单而遗漏链路。

**组件与工具副作用**：涉及提示、关窗、回填或状态恢复时，追到页面实际加载版本的组件或公共工具及调用顺序，核对隐式关闭、替换、默认处理或共享状态等副作用；调用处未显式执行不等于结果未发生。隔离验证保留决定结论的真实实现或已核实的等价行为，仅替换无关依赖；简化 Mock 删去关键行为时，不能用其证明现状或 Bug。分别标明源码、隔离探针和实际运行环境的证据范围。

**证据核对**：有业务意义的动态展示值、跨服务字段类型和员工权限须有可定位证据，标明环境、版本及未核实部分。涉及这些问题时，按[证据核对指导](evidence.md#证据核对)读取所需小节；字段名、页面透传或单个账号的授权列表不足以证明完整契约。

**展示与计算兼容**：金额、天数、档位等计算应查明单位、公式、精度及取整位置；结果变化属于业务变更，须经用户确认。用户要求沿用旧行为时，有业务意义的动态值显示口径也是兼容基线；接口字段类型或序列化方式变化不得默认改变单位、精度、状态文案、组合方式、脱敏规则或空值占位等可见内容，确需改变时列明差异并取得确认。

## 证据核对

现状、产品、方案、审查和测试模式涉及下列问题时，按需读取对应小节；这里只提供取证方法，不把现状自动变成目标规则。

### 动态展示值

对有业务意义的动态展示值，沿旧页面模板、转换逻辑和接口映射追到原始提供者，分别核实源值、各处转换和最终可见内容；同一来源在不同区域须分别核对。字段名、类型或另一处的格式不能代替当前展示位置的证据。

核对页面实际调用的模板引擎、格式化器或组件及其插值/默认处理；表达式返回原值不等于最终显示原值。按实际分支区分字段缺失、null、空串和零值，记录显示内容及是否影响整次请求成功，不从新接口的可空类型反推旧结果。

依赖结果参与聚合时，分别追踪成功的零值/空结果、结构缺失、业务失败及抛错/超时到最终信封与呈现；不能把失败兜底出的零值当作真实无数据。必要依赖失败应按已确认契约承接，不靠HTTP成功或部分字段有值证明业务成功。旧行为如有缺陷，仍按确认范围安排修复，不自行扩展到其他链路。

文本安全沿保存、响应、展示和回填分别核对实际上下文及消费方式，不以输入清理代替展示安全，也不要求所有接口返回HTML转义值；原始JSON字符串配合安全文本展示可以满足目标。涉及安全修复时，验证零值、空结果及其他依赖失败分支不会绕过相应保护，不把安全展示挂在无关请求成功条件下。

### 输入处理与校验兼容取证

涉及输入清理、格式转换或内容校验时，按实际操作追踪页面提交、服务端处理、保存返回和编辑回填，记录各阶段输入、输出及处理顺序。创建与编辑等入口分别核对；函数名称或相似工具不能证明等价。

兼容结论追到决定结果的最后消费点：原始输入 → 各层转换与判分 → 最终筛选/保存 → 展示或回填。中间条件可能被后续阈值判断、默认值、覆盖或重新拆分改变；查明每次使用的是原输入、检测副本还是上一步输出。提供方不可取得时，只确认已证阶段，明确缺失阶段会影响哪些结果，不把中间参数当成最终命中集合。

只核对实际影响结果的语义：空白与空值判断、标签/实体处理、繁简或大小写转换、长度及匹配单位（按实际区分字符、码点或字节）、词条作为字面文字还是匹配表达式、多个命中的选择顺序，以及返回值如何被调用方判为拒绝。共享工具须查实现及调用处，不能只看到“命中”就省略其返回值消费条件，也不把某页的词库、分组数量或算法固定为通用要求。

涉及词库、字典或规则文件时，资源可用且版本相同仍不能证明消费算法等价；明确决定结果的解释方式，并用区分性输入及准确结果核对。可复用现有服务或库，不默认新增组件、冻结资源或迁移提供方。

用能区分处理顺序或候选实现的隔离输入核对结果，分别记录源码已证实的行为与尚缺的运行、部署或动态数据版本证据。用户已确认承接的可见结果按[产品输入规则](business-requirements.md#输入处理与校验的可见结果)写入产品正文；来源冲突或确需改变行为时保留决策点，不以新工具的默认行为填补目标。

根据实际处理选择少量区分性样例，不机械生成全部组合：

| 已发现的处理 | 样例选择与核对终点 |
|---|---|
| 空值/真假值判断或默认值 | 对照缺失、null、空串、零及相近非空输入，核对条件是否省略、是否拒绝及实际展示 |
| 模式匹配、拆分或再次判分 | 对照匹配字符与字面字符、首尾分隔符、空项和项内空白，核对最后使用的匹配方式及结果 |
| 范围、阈值与单位转换 | 对照边界前/等于/后，核对最终比较方向、等号及条件是否仍存在 |
| 多条件覆盖或组合 | 选择能区分处理先后、覆盖/保留及同时满足/任一满足的组合，核对最终生效条件 |

### 字段类型

跨服务字段的序列化类型须以实际提供该字段的服务源码或可靠响应为证；调用方透传和页面展示不足以确定类型。无法取得这些证据时，将所需源码或类型列为待确认问题；生成产品需求时按参考文件的取证后集中提问流程向用户确认，答复前不把推测写成已确认契约。

### 员工权限

涉及权限时，区分调用方传值、权限服务的定义目录或枚举与校验逻辑，以及特定账号的授权列表，标明证据的环境、版本和列表范围。只有已确认现行完整权限目录缺项且校验链路拒绝时，才认定该权限当前不可授予；单个账号列表缺项仅证明该账号未获授权。代码或目录已能确定的事实直接写结论，不笼统列为待联调；部署版本与账号实际授权等未验证结果才列联调。先查可访问证据，来源冲突或目标页面行为仍有实质歧义时再询问用户；不凭调用方常量生成不可达的授权场景，并使需求、方案、接口和测试口径一致。

## 接口码与前端动作

规划重构后接口的报错呈现时，按已核实的落地项目契约及已确认要求确定成功与失败、错误标识和文案职责，不预设字段名。采用服务端业务文案的契约，由后端维护文案，前端按契约展示并负责固定文案、兜底和界面交互，不另建重复的业务文案映射；采用错误标识及参数、由前端翻译的契约，复用项目既有翻译资源和请求封装，不为本技能新增服务端文案字段或改造公共错误协议。前端按实际契约决定提示位置和后续动作。职责缺证或要求冲突时核实依据、列明受影响分支，不自行选择另一种协议。沿用旧行为时，核对并保持最终用户可见的准确报错文案，不要求它必须作为接口原文返回；查询无结果等正常业务结果按已确认的业务语义处理，不因文案职责改为接口报错。

对页面直接调用的每个接口，列出请求阶段与触发动作、前置身份/权限、请求契约、成功结果及可空字段。特殊失败逐项写明触发条件、HTTP/响应信封、错误码及实际序列化类型、前端动作和状态恢复。核对旧新错误码及类型、前导零、下游码的消化或映射、同码不同来源，以及公共拦截器与页面是否重复提示或漏掉登录跳转。区分业务失败、字段校验、未登录、无权限、响应数据不完整、网络/超时和取消；明确可读文案与兜底，不把框架异常文本直接展示给用户。无来源依据时不指定具体错误码或弹窗样式。上述页面动作在开发方案及测试中展开；新接口文档的内容边界见[新接口文档指导](migration-plan.md#新接口文档)。

按本节的消费判定规则处理旧错误码：有调用方按码执行特殊业务动作时保留语义并写明兼容方案；没有特殊消费时按落地后端的通用规范映射。内部消化的下游码不得误列为页面接口返回码。

## 落地结果审查

方案中的约束清单标明来源、目标行为和待确认项；不替具体页面预设业务答案。待确认事项只阻止依赖该决策的后续开发。审查落地结果时按实际影响验证关键身份/权限、请求阶段和成功/失败组合，检查错误码对应动作、局部状态、重试、重复请求、失败后的数据与副作用。报告已验证、未验证和与旧行为有意不同之处；验证规模与风险相称。
