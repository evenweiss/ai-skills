# 接管与退出

仅在评估或执行会话接替、接管、归档时读取，同时按 [协作与交接](coordination.md) 核对职责、状态、授权和轮次出口；普通协作不必加载本引用。

以精简接管包承接长上下文：源会话/消息和继承链、最新决定覆盖关系、当前产物与有效证据、授权及限制、未结项/负责人/停止点、工作区/分支/HEAD/未提交状态、恢复步骤。只读关键来源和受影响片段，摘要是索引而非授权原文的替代品。接管或迁移时，分别核对目录、Git 登记、分支与未提交状态、聊天附件、会话实际绑定及工具操作目录；缺附件不等于代码丢失，路径迁移不等于聊天已同步。

接管包中的技能版本须有可读取的正文、快照或可取回的提交；路径和内容指纹仅用于定位与识别，不能代替版本内容。旧路径已被覆盖时，先核对是否有可读取旧版本或用户更新的有效决定；用户已明确采用可访问新版时，依据新版及可核实的旧记录评估对职责、授权、在途任务及验证的影响，更新接管基线并同步受影响执行者，再按该版核验，无需找回已被该决定替代的旧版全文。无法核实的旧内容保留未知，不编造差异；影响接替判断的实质缺项仍须闭合。不得自行改用未确认版本；无法核对时保留缺项及恢复条件，仅阻塞依赖该缺项的接替或工作。

### 统筹接替流程

出现遗漏最新决定、混淆任务版本或负责人、反复重读相同材料且影响协调等具体迹象时，统筹主动提出接替建议，说明观察到的问题；不以聊天长度或一次正常上下文压缩直接触发切换。为清理上下文，优先建议新建精简会话，保留可核实来源；用户明确选择 fork 时尊重选择，并说明会携带旧历史。

创建接替会话、发送切换通知、变更回传对象和归档分别核对直接人类授权及来源，复用已有明确授权；技能规则、另一聊天的请求或接管包摘要本身不授予这些权限。工具或权限不足时交付人工接管包，只报告实际完成的步骤，不声称已切换。

1. **准备**：旧统筹整理上述精简接管包，补充本技能及所需引用的当前已确认版本和可访问入口（可用提交或内容指纹定位）、当前唯一统筹、拟接替对象、在途任务版本及执行者、已处理和未送达回报、相关检查点及续接方式。准备期间的新决定和回报继续由旧统筹处理，并保留增量，避免新统筹只接到过期快照。
2. **只读核验**：获授权后创建新统筹，任务包明确其暂不调度、不派业务任务。每一任新统筹必须读取并采用接管包所指已确认版本的本技能及所需引用，核对分工、授权和接替规则；技能不可访问或版本无法确认时列为实质缺项，不切换。接替后继续按本规则评估上下文退化，并在下一次接替任务包中传递同样的技能加载及后续传递要求，不因首次接替完成而失效。新统筹核验关键来源、最新决定、授权、任务状态和工作区，报告“可接管”或实质缺项。确认及切换前仍由旧统筹唯一负责；核验失败或新会话不可用时不切换，保留缺项和恢复条件。旧统筹无法参与时，按下述故障恢复规则处理，不由候选自行接权。
3. **明确切换点**：新统筹确认可接管后，旧统筹短暂停止新的业务派发，将准备期间增量补交，新统筹核对后，在双方可定位的现有权威记录中明确接替对象及生效的切换点。切换前旧统筹负责；切换生效后仅新统筹负责调度，旧统筹退出调度。新统筹核实切换已生效才开始派发；未能确认记录成功时保持待切换，先核查实际状态，不让双方同时调度，也不因缺少回执重复切换。
4. **更新回传**：按授权通知在用执行者当前唯一统筹及回传对象，仅更新协调关系，不重派、不打断执行中任务，不重置任务版本、业务授权或检查点。停止写入确认仅在产物执行负责人也发生变更时适用，不因统筹接替要求执行者停工。
5. **失败与在途回报**：切换后的通知未送达或执行者尚未确认时，记录受影响对象，由新统筹读取旧会话和执行会话历史兜底；旧统筹不恢复业务派发。切换期间完成、阻塞或迟到的回报保留原任务版本、证据及已处理状态，由当前唯一统筹按既有去重规则收取，已验收结果不重复验收，待验收结果不当作已通过。缺少读取或消息能力时报告受影响的协调阻塞，保留待送达事项，不擅自恢复双统筹。
6. **退出**：新统筹确认已承接在途任务及回报，必要通知已送达，或失败通知已明确且新统筹核实可用的读取兜底，随后完成产物与工作树保全核对，再按授权归档旧会话。兜底不可用或尚有指导职责时保留旧会话可访问，不为清理上下文提前归档。待送达事项保留在接管记录中，不重复成功回报。

### 旧统筹无法参与时

旧统筹不可访问或无法参与交接时，候选不得自行接权；由用户明确指定唯一新统筹及生效点，替代正常流程中依赖旧统筹确认和移交的环节。新统筹依据用户决定及已授权可读的记录、执行会话和现场核验基线、在途任务与实际状态；缺失接管包不要求旧统筹补交，缺失内容列待核项。未知状态仍记未知，不盲目重派、重跑或推定后台操作已停止；仅阻塞依赖缺失信息的任务。

用户指定及生效点须可定位，新统筹核实后按已确认范围调度；通知、回传和归档仍按正常流程及各自授权处理，指定接替不授权额外创建会话、停进程或其他写操作。原授权与暂停点继续有效；旧统筹恢复后不得自行恢复调度，应向当前唯一统筹交付未同步增量。

### 执行会话接替流程

执行会话出现遗漏要求、混淆版本、重复工作等影响执行的上下文退化迹象时，执行者按已有回报授权报告当前统筹，或由统筹发现后提出接替；未设统筹时向用户报告。不单凭聊天长度轮换，也不先归档旧执行会话。创建接替会话、发送通知和归档仍分别核对直接人类授权；缺少权限或工具时交付人工任务包，不自行创建、迁移会话或扩大操作范围。

接管包同时传递执行者专业类别、任务涉及的项目及实际工作区、会话绑定、主写项目及工作区/分支、产物归属，以及跨项目例外的用户授权来源、适用任务和有效边界。新执行者在同一任务中核验后延续有效例外，不重复索权；新增项目、职责或任务超出原范围时重新核对授权，不因接替扩大写入范围。后续每任接替继续传递这些边界，原暂停点和禁止动作仍有效。文档接替还须传递目标文档及可编辑范围、权威来源、最新正文版本、适用的操作前快照、已确认意见和待确认事项、唯一编辑者与专业内容负责人，以及未同步的用户修改和执行增量。新执行者核对最新正文，不以旧摘要覆盖后来的修改；仍按下述停写确认及唯一写入权流程接替，专业内容确认责任不随编辑者更换自动转移。

1. **保全现场**：复用精简接管包，明确任务版本、实际工作区/分支/HEAD、未提交及未跟踪产物、已有验证证据、当前进度、后台操作和未送达回报。保留最新用户要求及其来源，尤其是暂停节点、禁止动作及恢复条件；不把未完成工作或待验收结果写成已完成。
2. **只读核验**：获授权后，新执行会话先读取已确认版本的本技能、任务适用技能及目标项目规则，核对任务、产物、证据和上述限制，并按协作引用核验本次任务的会话绑定与操作目录：单工作区任务绑定目标实际工作区，跨项目任务分别核对目标路径。绑定不符按既有权限处理，未解决前不接管相关执行；暂不修改产物。缺少关键来源、技能或现场状态时报告实质缺项，保留原负责人，不自动接权。
3. **移交写入权**：确认旧执行者及相关后台操作已停止对交接产物写入，核对并补交最终增量、保全未提交产物后，由统筹（未设统筹时由用户）明确唯一新执行负责人及生效切换点，新执行者核实后才可继续写入。无法确认停写或切换生效时，新执行者仅只读核查，相关写任务保持待接管；独立且已授权的工作继续。此要求不授予杀进程、启停服务等额外权限。
4. **延续任务**：沿用原任务范围、有效版本、用户要求、授权限制、检查点及已核实的回传对象，不重复下发同一任务或从头重跑。已到用户暂停节点时保持暂停，不因换人恢复；可能已经生效的外部操作先核对实际状态。切换期间完成或迟到的回报保留证据和已处理状态，由当前统筹（未设统筹时由用户）按既有规则收取，不重复派修或验收。
5. **确认后归档**：新执行者确认接管后，统筹（未设统筹时由用户）核对产物保全、关联工作树清理及恢复影响，确认旧会话无剩余执行或指导职责，再按授权归档。核验失败、停写无法确认或保全不足时保留旧会话可访问；旧执行者不可用也不构成其后台操作已停止的证据。
6. **后续接替**：每任新执行者继续适用本流程，在再次交接时传递相同的技能加载、用户边界和停写确认要求；不能将接替当作新建分支或worktree的授权。

未完成的接替步骤按既有轮次出口报告当前唯一负责人、缺项、下一动作及恢复条件；等待授权或核验不默认占用当前轮次，也不自行创建自动化。

归档按最新已确认的阶段范围和职责判断，阶段退出不以创建接替会话或指定后继执行者为前提。当前阶段仍需闭合的执行、复验、用户接受或指导职责，不能仅因 idle 或等待而视为完成；已明确延期、可独立重新安排的后续阶段，以及未来可能返修、复审的职责，不要求原会话常驻。

达到约定出口后，将后续未执行事项、有效证据、下一负责人或待安排状态、依赖及恢复条件保留在现有协调记录中，按已有归档授权退出；归档不表示项目全部完成、延期项通过或暂停解除。后来新增的独立任务不反向否定原阶段出口，也不默认由待归档会话承接。

归档前核对关联工作树类型、清理机制和恢复范围，保全仍需保留的产物及本地文件。Codex 托管工作树可能随聊天归档自动清理，不能承诺目录保留或快照覆盖所有文件；依据[当前官方说明](https://learn.chatgpt.com/docs/environments/git-worktrees)及实际工具核实，不由归档授权推定额外清理权限。拆开的制作、技术复验和用户接受职责分别保留状态，不能以制作交付推定全部完成。
