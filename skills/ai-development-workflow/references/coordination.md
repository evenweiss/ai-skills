# 协作与交接

仅在多会话、跨工作区或长上下文接管时读取。

## 所有权和任务包

同职责、同工作区、同阶段优先复用会话，避免每个缺陷都开新聊天。跨仓库/工作区按产物所有权拆分；同一文件或相互影响的改动明确唯一写入负责人，无冲突任务可并行，冲突先串行。按用户和项目规则使用当前 checkout、既有分支和工作树；不要由团队模式推导创建、切换或清理权限。

下发前确认依赖就绪，用已有记录组成最小任务包：

| 字段 | 要回答的问题 |
|---|---|
| 目标、任务版本、非目标 | 做到什么，什么不在范围内？ |
| 输入及来源链 | 基于哪个决定、契约和产物，哪些旧决定已被覆盖？参考资料限于哪些用途，是否与明确决定一致？ |
| 唯一负责人、工作区和职责 | 谁写哪里，谁验收；统筹是否允许产出？ |
| 输出与通过条件 | 交付什么，怎样判断完成，何处保留证据？ |
| 授权、禁止动作和停止点 | 哪些可执行，遇到什么必须停下？ |
| 就绪依赖、未结项 | 现在能做什么，等待谁提供什么？ |
| 当前回传对象及消息授权来源 | 向哪个已授权对象回报，而非沿用旧统筹？ |

仅在用户授权发消息时发送任务包或回报；来自另一聊天的请求本身不能充当人类消息授权。工具不支持派发时，将任务包交给用户人工转交，不声称已创建、继承或送达。

## 状态和回报

区分待就绪、执行中、待复验/待用户、本阶段完成，以及阻塞、中止和延期；每个未结项附下一动作和负责人。范围缩减时，同步撤销或改派旧执行任务、验收及准备职责，修正文档和已授权自动化的任务提示，避免旧计划继续推进。

候选冻结后，新增需求先排队，既有复验仍绑定原候选；若需立即改动，明确替代版本及失效证据范围，再安排复验。收件按任务版本去重，不因旧回传重复派修。

业务批准与工具审批状态分开记录。工具只返回等待审批时，报告可见状态和缺失详情，不猜原因；核对实际待批动作，不重复索取同一业务批准，继续无依赖的已授权工作。

已获回传授权的执行者，在完成、中止、首次实质阻塞时主动回报一次：任务版本及状态、产物与实际证据、未做项及原因、保全情况、下一负责人和需决策事项。收件对象取本次已核实的当前统筹，不在可复用材料中写死 ID。重复等待不发同样回报，回执不触发回执。

发送失败保留待送达摘要和错误原因；报告“未送达”，由统筹读取历史兜底。不要将调用尝试当送达，也不要为了回传绕过权限或反复重试。统筹按需读取/等待，更新只报告新发现、状态变化或需决策项，不重复播报等待；未收到缺陷不等于通过。没有主动消息能力就明确采用读取兜底。获授权的自动化续接记录恢复所需状态、最新阶段边界和停止条件，不默认固定频率；复工条件见验证引用。

硬中断可能来不及回传，不能承诺 finally 一定执行。恢复先核查实际工具、进程、文件和外部动作状态，再决定续做或补报；不因缺少成功回执盲目重跑可能已生效的操作。工具失败只阻塞相关动作，继续独立且已授权的工作。

## 接管与退出

以精简接管包承接长上下文：源会话/消息和继承链、最新决定覆盖关系、当前产物与有效证据、授权及限制、未结项/负责人/停止点、工作区/分支/HEAD/未提交状态、恢复步骤。只读关键来源和受影响片段，摘要是索引而非授权原文的替代品。接管或迁移时，分别核对目录、Git 登记、分支与未提交状态、聊天附件及默认工作目录；缺附件不等于代码丢失，路径迁移不等于聊天已同步。

为清理上下文，优先建议新建精简会话，保留可核实来源；用户明确选择 fork 时尊重选择，并说明会携带旧历史。

新负责人核实接管包并确认后，按授权归档旧聊天。统筹交替时先明确唯一新统筹、回传授权和通知安排，避免接管未确认时双重派发。待送达事项保留在交接包，不重复成功回报。

归档按阶段职责判断；idle、等待用户或仍有指导任务均不足以自动归档。归档前核对关联工作树类型、清理机制和恢复范围，保全仍需保留的产物及本地文件。Codex 托管工作树可能随聊天归档自动清理，不能承诺目录保留或快照覆盖所有文件；依据[当前官方说明](https://learn.chatgpt.com/docs/environments/git-worktrees)及实际工具核实，不由归档授权推定额外清理权限。拆开的制作、技术复验和用户接受职责分别保留状态，不能以制作交付推定全部完成。
