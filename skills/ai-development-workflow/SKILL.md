# AI Development Workflow

用最少的协调成本，使需求、实现、验证和交接始终指向同一基线。按任务需要取用以下规则，不把所有任务展开成完整流程。

## 先选组织方式

先读项目已有工作流与最新用户决定，判断工作区、依赖、风险和独立验证需要；复用项目的分类和需求/契约机制。项目采用或要求 OpenSpec 等机制时才沿用，不自行引入统一门禁。

| 条件 | 选择及代价 |
|---|---|
| 单仓小改、短周期、低依赖 | 单执行会话，直接实现和比例验证；无需团队、矩阵或交接仪式 |
| 少量独立工作，用户选择亲自衔接 | 用户协调独立会话；上下文隔离清楚，用户承担依赖和授权转述成本 |
| 多工作区、有阶段依赖或需独立验收 | 可建议单统筹＋按需执行会话；减少用户协调，增加交接成本和统筹单点风险 |

先核对用户选择和实际工具能力。统筹是否只管理、执行者是否必须独立主会话，属于本次协作约定，不是固定平台规则。职责以用户要求为准。角色按缺口启用，不默认全开前端、后端、产品、设计和测试；不设固定审查人数或分数。

本 Skill 不授予创建会话、委派、消息、分支或 worktree 等操作权限，授权边界见下文。没有多会话工具或权限时，在单会话按阶段执行，或交付人工任务包。不要把独立主会话当作具备子 Agent 的继承、通知或上下级保证。

采用多会话或需要接管时，读取 [协作与交接](references/coordination.md)。环境受限、使用 Mock、多方验收或准备切换发布时，读取 [验证与阶段出口](references/verification.md)。

## 维护一条可定位的基线

复用现有任务、文档或聊天记录；只补影响决策的缺项：

- 当前目标和非目标、输入资料及版本、验收点、工作区与负责人。
- 最新用户决定的来源、覆盖的旧决定、影响的设计/契约/代码/用例、待同步责任人。
- 依赖、已授权动作与限制、交付条件、当前停止点。

文档链接或 ID 只证明可定位，不能证明正文已核对或同步。同步外部文档另核授权、最新内容和准确操作前快照。保留来源链，避免交接摘要抹掉用户后来的纠正。设计先行或代码先行按本次决定，注明当前权威基线、同步方向和接受后待同步项，不默认设计稿始终领先。

需求→设计→接口→代码→用例→证据应能互相定位，无需复制成多套表。复用已有组件、主题和设计依据，先核锁定版本的公开能力与实际数据来源；能力缺口明确降级或待决策，不凭设计补造接口能力。可访问性或质量检查不能自动变成新增视觉、业务或权限规则。缺少预期且会改变行为时再澄清。

跨接口版本或迁移时，分别标明生产者契约和消费者适配版本，不编造冻结版本。对齐字段/类型/空值、错误、身份来源和资源归属、写入及顺序语义、样例与兼容差异；Mock 绑定所测路径的版本。契约就绪才并行依赖实现，未就绪可做独立准备。

## 按授权推进到可证明的出口

复用已明确授权，常规实现选择不重复询问。方案批准、本地开发、提交/推送/合并、部署、配置发布、远程主机变更、直接 DB 写、真实 API 写和消息发送的授权范围分别核实，不能相互推定。任何流程建议均不能降低系统、用户、项目或工具边界；服务操作人和自动化策略取决于本次授权。

对明确未授权的写操作，先说明目标环境、具体动作和影响，再取得所需授权；“测试”“修复数据”“恢复环境”不是写入权限。暂停和等待不会自动扩大或恢复授权。

按实际验证方式和覆盖范围报告结论；环境受限与证据边界见验证引用。

阶段结论写清：已证明范围、当前版本和证据、未闭合项及负责人、下一动作与准入条件。idle、turn 结束、代码交付或方案高分均不等于业务完成。若使用评分，只评价约定维度的方案成熟度；阻断未关闭不能靠总分放行，更不能据此声称软件正确。

小改在影响范围验证并查看最终差异后直接交付；协作阶段按约定验收出口收口。仅对变化和具体风险补验，不为流程重复全部历史。
