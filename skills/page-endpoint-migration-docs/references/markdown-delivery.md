# Markdown 文档组织与交付

涉及目录、标题或主文档时读对应小节。更新或新增本地 Markdown 文件时按末节回读检查。

## 适用范围与目录

- 按[迁移范围](../SKILL.md#选择迁移范围)先裁剪目录：仅前端不增后端方案或新接口空篇，页面相关的仅后端不增逐页面前端方案，指定项目只组织该项目方案和必要依赖。推荐层级不是全栈硬性清单；单篇可兼任入口。
- 制定文档生成方案时，先与用户确认完整需求名称，再据此确定总览标题和目录。用户已明确给出名称时直接沿用。
- 完整迁移以一个迁移总览为入口，按交付物分组，组内按业务模块、页面、端或项目拆分。只建设用户要求的交付物；单篇任务不自动生成完整目录。内容归属见[文档归属与同步](document-review.md#文档归属与同步)。
- 现状梳理每个页面独立一篇，由现状总览统一管理；页面保留后端链路摘要，复杂或共享后端逻辑按需独立成文档。仅提供已有能力的依赖项目可在调用处记录必要契约和影响，不要求每个后端项目独立成篇。
- 重构前、后产品需求分别组织，旧、新接口分别组织。每类可集中覆盖多个页面，也可按业务模块或接口提供项目拆成多篇，均有统一入口；同一接口契约只维护一份，明确提供项目、消费页面及调用差异。
- 开发方案有统一入口。多页面全栈迁移按业务页面分组，每组列出本次确需实施的前端、后端方案，并直接链接对应文档。两端均独立实施时，每页各一篇前端和后端方案。页面分组可以用总览正文承载，页面特有的依赖与实施顺序就近说明。单端或指定项目按前述规则裁剪，共用后端实现保留唯一主描述。后端可在一篇中按项目分章，规模或实施安排需要时按项目拆篇；同一页面涉及多个端或前端项目时明确各自落点，继续拆篇时由该页面方案提供入口。重定向、菜单链接替换等已确认事项放总览或专项子页，不自动纳入范围。
- 测试与验收按业务场景、模块或测试层级组织，拆篇后保留统一覆盖与执行入口；Bug 汇总独立于现状和方案，涉及时才创建。
- 总览须说明范围、关系、状态及阅读入口，不复制下级全文。某类内容只需一篇时，由该篇兼任总览，不增加只有链接的中间层。有迁移总览页时，总览页标题使用已确认的完整需求名称。日期前缀仅按用户要求使用。下级页标题只写内容名称，如“业务现状梳理”“重构后产品需求”“后端开发方案”，不重复需求日期、具体需求名或完整业务路径，也不添加日期后缀；同类内容拆成多篇时，只保留区分页面、业务或项目所需的范围名称。无总览页时，标题仍须能识别所属迁移、交付类型及适用范围。
- 按用户的目录要求组织文件，跨文件导航使用相对链接。
- 涉及 Bug 条目时，现状梳理、旧接口和迁移方案的编号指向独立汇总文档的稳定条目锚点；汇总条目反向链接来源、实施任务及已存在的目标规则、接口和用例。关闭问题仍保留编号与锚点；目标需求、新接口和用例不反向标记 Bug 编号。核对每个相对链接及其对应的章节或条目标识。
- 分类总览与实际下级文档互链，页面现状和方案定位到适用的接口条目，不要求接口分别从属于单页现状或方案。复用现有页面、编号及锚点；移动、改名或归并须在授权范围内保留独有内容并检查相关引用，不重建覆盖。保存后核对目录、正文和链接。

### 推荐层级

```text
业务迁移重构｜总览
├── 现状梳理｜总览
│   ├── 页面 A 现状
│   ├── 页面 B 现状
│   └── 后端项目现状（按需）
├── 产品需求｜总览
│   ├── 重构前产品需求（可拆篇）
│   └── 重构后产品需求（可拆篇）
├── 接口文档｜总览
│   ├── 旧接口文档（可拆篇）
│   └── 新接口文档（可拆篇）
├── 迁移开发方案｜总览
│   ├── 页面 A 前端方案
│   ├── 页面 B 前端方案
│   ├── 后端开发方案（可按项目拆分）
│   └── 入口切换等专项方案（按需）
├── 测试与验收
└── Bug 汇总与修复方案（涉及时）
```

以上是完整交付的推荐形状，不是每次必须创建的页面清单。

## 主文档与开发发布信息

交付已包含产品或开发主文档时，按下表维护阅读入口；单篇文档任务不自动增建主文档。沿现有结构覆盖所需信息，不固定章节数量，也不复制下级完整规则。

| 主文档 | 当前应能回答的问题 |
|---|---|
| 迁移总览 | 本次业务目标、范围与排除项是什么；关键链路如何贯穿页面、端与项目；各类文档入口、总体状态及关键未决事项在哪里 |
| 现状总览 | 旧链路全貌、页面与后端关系、共享逻辑归属、取证覆盖及缺口是什么 |
| 产品主文档 | 为谁解决什么问题；本次目标和范围是什么；重构前后需求在哪里、各自负责什么；当前确认/开发/验收状态及仍待决定事项是什么 |
| 开发方案总览／开发主文档 | 改哪些项目、复用哪些依赖；各页面前端、后端及专项方案在哪里；共享技术安排、任务依赖、跨项目联调、发布顺序、回退及开发发布信息是什么 |

多页开发总览集中说明跨页交接的预期结果和各页职责，并链接适用方案章节和实际覆盖该交接的验收条目。联调、发布与回退按执行事项记录，注明适用页面及已确认的依赖和顺序。

复用总览或现有范围表记录必要关系：业务场景 → 页面与端 → 接口及提供项目 → 实施任务 → 验收用例。按文档职责保留必要信息，不要求产品正文写接口或代码，也不为映射另建交付物。分类总览中的状态与对应正文、证据一致，具体职责沿[归属规则](document-review.md#文档归属与同步)。

开发主文档需跟踪实施发布时，单独维护下表：

| 落地项目 | 开发分支 | 提测日期 | 上线日期 | 上线 TAG | 回滚 TAG | 备注 |
|---|---|---|---|---|---|---|

表内只列实际需要修改的项目；仅复用已有接口的依赖写在项目范围说明中。未提供的信息集中询问用户，已明确留空的字段直接留空；已有答复不重复询问。未知字段可以留空，不从本机分支、源码提交或取证日期推断发布信息。

## 当前正文与历史

- 新建或获授权整理版本化正文时，默认按主题维护当前有效内容，修订流水由现有版本记录承接。用户要求审计记录或变更对照时，按其要求保留；普通局部更新不因此获得清空其他历史块的权限。
- 历史块含仍有效的规则、准确文案、边界示例或决定时，先将独有内容归入对应正文，再删除已获授权清理的流水。正文不靠日期补充章或历史附录补齐当前要求。
- 源码提交、采集日期、来源文档版本、生效决定及发布履历属于有效依据，按用途保留。区分冻结取证基线、当前引用版本和实际发布记录；不机械升级冻结版本，也不把编写过程写成发布履历。

## 文件更新与回读

- 写入前读取最新正文，在用户授权的路径新增文件或定点更新。保留无关修改、稳定编号、有效锚点与来源。将尚未明确的规则标为待确认。
- 仅链接实际存在的文件和条目。跨文件使用相对路径，已有显式锚点继续复用。核对文件名、链接片段和目标内容。外部资料仅作来源引用。
- 保存后回读正文和差异，核对内容、引用与用户要求一致。报告 Markdown 文件位置、尚待决定的问题及未验证项。
