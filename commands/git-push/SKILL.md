# Git 提交与推送

按用户授权完成提交前审查、提交或推送。遵循当前项目规则，技能名称不代表额外授权。

## 操作边界

- 用户明确调用本技能并要求只审查：只读检查和报告，不暂存、不修复、不提交、不推送。
- 只提交：审查通过后提交指定改动，不自动推送。
- 提交并推送或明确调用本技能且未限制动作：执行完整流程。只要求推送已有提交时，不创建新提交。
- 审查发现实质问题：报告位置、影响和修复建议，停止提交/推送，不自动修复。后续用户授权修复后，验证修复再继续已授权流程。

## 执行

1. 确认仓库、当前分支、工作区及暂存区；读工作区与暂存区 diff，识别用户指定文件或改动块。已有无关改动和暂存内容保持原样。
2. 审查目标改动及必要的直接上下文，执行项目要求且与范围相称的检查。发现敏感信息、公共受控副本、依赖/构建契约限制时遵循项目边界。改动涉及样式、布局或交互时：先本地启动页面截图自检并随审查结论附截图，再进入提交——agent 看不见渲染结果的 UI 交付，约 70% 问题本可在这一步拦截（用户估算，2026-09 复盘）。
3. 提交前核实实际提交范围恰好是用户授权范围。不使用无差别暂存；文件中混有其他改动时按块隔离。无法安全隔离或无法确认归属时询问，不擅自清空他人暂存内容。
4. 按主要变更意图生成 Conventional Commit：`<type>(<scope>): <subject>`。scope 可省略，body 用中文解释背景和关键改动；不要仅凭文件扩展名判定类型。
5. 只执行已授权动作。推送前确认目标 remote、branch/upstream 和将被推送的提交集合；不能只看最新一个提交。目标不明或包含未授权提交时先确认。禁止擅自强推、切分支、改历史或处理远端冲突。
6. 回读提交文件清单、提交哈希和推送结果，确认未夹带无关改动。失败时报告停在哪一步，不把本地提交成功写成推送成功。

## 交付

简要给出审查结论、实际验证、提交哈希及远端分支（如执行），列出阻塞或未执行动作。无需重复输出项目身份和整套流程模板。
